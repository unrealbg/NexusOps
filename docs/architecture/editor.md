# Goal 02C remote text editor

The Files workspace exposes **Edit** for one selected regular remote entry. Rust opens the exact path over the current `HostId` / `HostSessionId` / `SftpSessionId` SFTP v3 session. `LSTAT` and handle `FSTAT` must identify a regular, non-symlink file with size, mtime, raw POSIX mode, uid and gid. Reads are capped at 1 MiB plus one byte, irrespective of the server's declared size. A changed file during the read is rejected. There is no generic byte-read or arbitrary remote command IPC.

Only strict UTF-8 without NUL is accepted. A UTF-8 BOM is recorded separately. Uniform LF and CRLF are normalized to LF for the textarea and encoded back to their original convention for saving. A final newline is preserved; a file without one stays without one. Lone CR and mixed newline styles are rejected. Content is rendered as text; control and bidirectional characters in displayed paths are escaped. The text buffer lives only in component-local memory. It is never placed in Query, Zustand, browser storage, audit or logs.

Opening records an immutable server-held document authority scoped to the three session IDs and exact path. It includes existing `EntryIdentity` semantics (kind, size, mtime), raw mode, uid/gid and a SHA-256 digest of the bounded original bytes. The digest catches same-size changes within SFTP v3's one-second mtime resolution. It is not a server-provided atomic compare-and-swap token. A document token expires after one hour and is consumed when a save plan is created. Clean/confirmed dirty Close and successful Reload explicitly retire the old token; ignored or delayed opens retire their returned token under its original session. An idle expiry task remains a fallback. Cancelled or failed plans require explicit Reload remote before another save attempt.

Save planning rechecks metadata and original bytes, validates the new encoded byte limit and creates a five-minute, in-memory, one-shot `FilePlanStore` plan. It binds the current session, exact path, original revision/digest and bounded new bytes. The renderer receives only plan metadata for review. Cancel discards the exact plan. Execution consumes it once and enqueues a job in the existing `TransferManager` so disconnect, reconnect, host deletion and shutdown use its SF-12 quiescence and cleanup barrier. SF-13's per-host lifecycle gate serializes planning against teardown.

The job rechecks the original, creates an exclusive same-directory `.nexusops-<uuid>.edit.part`, and trusts ownership only after a successful exclusive `OPEN` reply. It streams the approved bytes using the existing bounded upload path, fsyncs when `fsync@openssh.com` v1 was negotiated, and closes the handle. A refused or lost create reply never triggers removal. A known-owned failure removes only the exact staging path, and disconnect waits for this cleanup. After staging, metadata and content are checked again; immediately before `posix-rename@openssh.com` v1, they are checked once more while cancellation is still allowed. `Finalizing` begins only after that last full read and immediately before replacement. The original is never deleted first. A lost replacement reply is `OutcomeUnknown`, with no automatic replay. A confirmed replacement remains confirmed even if cancellation arrives after Finalizing.

The staging file starts with restrictive mode 0600. Before replacement, Rust applies the original POSIX permission bits (including special bits where the server allows them), attempts uid/gid preservation if they differ, and reads back mode and uid/gid. Failure or mismatch aborts and cleans owned staging. A nonprivileged server/account that cannot preserve required ownership fails closed. The OpenSSH interoperability test verifies ordinary mode 0644 survives a save. SFTP v3 does not expose ACLs, xattrs, SELinux labels, capabilities, hard-link count/identity or other filesystem-specific metadata; replacing a file may alter those. Users should not use this editor for files whose correctness depends on them. Metadata/digest revalidation followed by POSIX rename cannot prevent every concurrent remote writer between the final check and rename.

Disconnect or session replacement revokes pending document and plan authority. Closing or unmounting the editor retires in-flight requests; a delayed plan is discarded under its original session. An approval is published only if its captured text and buffer generation still match the visible editor text. Unsaved component-local text remains visible with save disabled until explicit Reload remote; conflicts behave the same way. Reload confirms before discarding dirty text. The UI marks successful saves clean only after the transfer reports `Completed`; failed, cancelled and ambiguous outcomes retain the local text and require reload. Physical `KeyS` with Ctrl handles save from anywhere inside the active editor; Alt, Meta, AltGraph and repeat pass through.

Native Windows acceptance remains **PENDING**. The owner checklist is: open disposable LF, CRLF and BOM UTF-8 files; verify unchanged round-trips and mode; edit and approve one save; cancel another; trigger an independent remote modification before approval and see Conflict with local text intact; disconnect/reconnect with dirty text and confirm Save stays unavailable until explicit reload; verify Ctrl+S on EN/BG layouts, AltGr pass-through and dirty-close confirmation. Use only the dedicated owner candidate after source review.
